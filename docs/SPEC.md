# WorkToScroll / WorkToWatch 产品要求

本文是已经确认的产品行为、体验边界和验收要求的唯一来源。已采纳的实现取舍见 [DESIGN](DESIGN.md)，实际代码结构见 [ARCHITECTURE](../ARCHITECTURE.md)，当前真机状态和未完成验收见[任务索引](../tasks/README.md)。候选方案、一次性测试和实现参数不进入本文。

## WorkToScroll

### 产品目标

WorkToScroll 通过工作或学习换取娱乐时间，并在可用时间耗尽后限制小红书使用。它面向希望减少无意识刷小红书的城市中产阶级年轻女性。

产品只根据可观察信号和用户设置行动，不声称判断用户的专注、身份、工作内容或工作质量。

### 娱乐保护与余额

- 用户完成必要授权后可开启保护；保护停止必须由用户主动操作，并清楚说明停止后不再扣减或阻止、已有余额保留。
- 有可用娱乐时间时，目标应用的前台使用从余额中扣除；余额耗尽后显示本产品的阻止页，用户可回到工具或桌面。
- 保护状态必须区分未授权、用户手动停止、服务中断和后台受限；授权存在或服务曾启动均不等于实际保护仍有效。
- 默认每日清零开启，可由用户关闭；本地时间的清零、余额结算和跨日恢复须保持一致，不能平白增加或丢失余额。
- 赠送时间是独立于余额的免费额度，只在用户设定的固定时间窗内可用：窗口内目标应用用时先扣赠送额度，扣完才动余额。未用完的部分在窗口结束时作废，下一次窗口开启重新给满；两个窗口不重叠，任一时刻最多只有一个生效。可分别开关夜间（22:00–08:30，45 分钟）与午间（11:00–13:00，30 分钟）。
- 主界面必须将攒得时间与当前生效的赠送时间共同计入“当前可用娱乐时间”，并分别说明其余量与结束时间。

### 工作、奖励与中断

- 开始工作需要用户主动操作。摄像头仅在工作过程中用于判断用户是否处于可观察状态；不保存连续画面，也不因应用冷启动、设备重启或锁屏而自动开启摄像头。
- 有效工作时间只在新的观察结果满足当前在场规则后累计。短暂不可靠或离开信号允许有限容错；持续中断后暂停计时，并按已选规则重置本轮尚未到账的进度。已到账奖励和历史记录不因中断倒扣。
- 可选工作奖励档位为每轮 10、15 或 20 分钟先获得 5 分钟娱乐时间；达到门槛后每分钟分别增加 30、20 或 15 秒。设置变化只影响其后新开始的轮次，不追溯改写已记录结果。
- 临时来电、通知、失焦或相机资源中断后，只在用户未手动停止、工作页重新可用且重新确认在场时恢复；中断期间不补计。恢复失败必须留下继续入口和明确状态。

### 反馈与日常界面

- 工作页显示清晰的计时状态和奖励反馈；颜色不能是唯一状态表达。
- 首次明确观察结果与有人/未见人的切换可使用提示音。提示音不能代替计时判定；用户可关闭，静音、通话或其他媒体环境不强播或补播。
- 异常暂停应明确提示，但正常切出、锁屏、手动暂停和正常返回不制造堆积提醒或把正常恢复误报为异常。
- 首页优先展示实际可用娱乐时间和实际保护状态；技术诊断和测试操作不进入日常使用路径。

### 隐私与限制

- 默认不上传或长期保存连续摄像头画面、页面正文、完整浏览历史、搜索内容、账户信息或观看内容。
- 摄像头在此版本不能可靠判断用户是否真的工作，也不能通过手机画面读取电脑屏幕。
- 厂商后台策略、权限撤销、系统强停及不同设备行为可能影响保护和监测；只有对应真机体验完成后才可声称该路径可用。

## WorkToWatch

### 独立产品边界

WorkToWatch 是独立于 WorkToScroll 的 YouTube 自律产品。两者不以系列副标题对外绑定，拥有独立品牌、商店商品、应用身份和用户数据；代码复用不表示用户数据、目标配置、文案或素材可以共享。

首发只解决官方 YouTube Android App 中的无意识或过量观看：有效工作或学习换取 Watch Time，目标应用前台使用消耗该时间，耗尽后显示 WorkToWatch 的阻止页。它不宣传为通用多应用管理器，也不声称区分 Shorts、普通视频或直播。

### 可用时间与保护前提

- 当前自用范围可提供夜间赠送时间；主界面必须将攒得时间与夜间赠送共同计入“当前可用娱乐时间”，并分别说明其余量与结束时间。
- WorkToWatch V1 的保护前提是用户先在系统设置关闭官方 YouTube 的 PiP，再在应用内明确确认。应用只能保存用户确认，不能伪装为已自动核验。
- V1 不监管、不计量或保留 PiP。用户重新开启 PiP 后，余额耗尽仍可能留下可继续播放的悬浮窗口，因此不得声称保护仍可靠。
- 未验证的 YouTube Music、YouTube Kids、YouTube TV、浏览器 YouTube、投屏、后台播放、锁屏音频、多窗口和跨设备场景均不属于已支持承诺。

## 当前范围与验收边界

- WorkToScroll 和 WorkToWatch 都仍处于分阶段验证。构建成功、静态检查、安装完成或单次设备路径通过，均不等于完整产品、长期后台可靠性、跨机型可用性、音频处理、商店合规或公开发布已完成。
- iPhone、PC 网站限制、手机—PC 联动、电脑摄像头、其他海外平台和多目标娱乐应用均不在当前交付范围。恢复其中任一方向前，需先确认新的产品范围、隐私边界和验收标准。
- 任何扩大数据收集、平台范围、外部账户/商店操作或用户可见承诺的改动，均须先获得明确确认。
