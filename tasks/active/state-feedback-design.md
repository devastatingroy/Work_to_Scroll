## 目标、范围与授权

- 2026-09-09 Roy 在认可样片后明确要求“请修改”，授权将该耗尽单幕接入当前 App；不扩展其他状态或皮肤商城。

- 用户要求检查哪些状态适合增加显眼、戏剧化、好玩的效果，以持续离开时弹出红色 WARNING 为例，并考虑未来短视频传播。
- 用户明确核心目标用户为“小红书重度用户，城市中产阶级年轻女性”，要求没有描述则补充。本轮已将该定位和体验目标写入 SPEC，并给 AGENTS 添加引用，属于直接执行本轮要求。
- Roy 进一步要求产品有让用户分享时感到骄傲的个性，否定只让提示更醒目的方案；随后明确同意先打磨“离开 → 人呢？ → 暂停 → 回归”的草案，并要求详细设计。本轮授权为设计，不代表 App 实施授权；毫秒参数与新增细节仍为建议默认值。
- 当前工作区已有设置、兑换/清零、监测恢复等改动，实施时在当前内容上接入，不回滚其他任务，不改变检测、计时、扣费或恢复判断。

## 当前检查结果

1. SPEC §6.3 已有容错后提醒、可观察事实、短视频展示的要求；§9 强调不频繁打断；§10 约定奖励轻量、不响铃、不震动、不弹窗；§11.1 已确定猫总举“人呢？”与到账形象。此前没有明确的目标用户，也没有完整的动效分级、入场/退场和去重方案。
2. [WorkActivity](../../app/src/main/java/com/roy/worktoscroll/WorkActivity.java) 的 `render()` 目前只改状态文字和猫图；AWAY 显示“持续未见人物 · 计时暂停”。`showRewardFeedback()` 已有 2.8 秒显示/淡出，不能描述为全 App 没有动效。
3. [WorkClock](../../app/src/main/java/com/roy/worktoscroll/WorkClock.java) 已区分 PRESENT、GRACE、AWAY、CHECKING、UNCERTAIN、PAUSED。在既有在场后持续未见人的路径上，离开容错是 3 秒；稳定回归确认是 1 秒。初次启动未见人可直接进入 AWAY，不能单凭 AWAY 枚举就演成“用户刚离开”。这些是当前代码事实，本设计不调整阈值。
4. 初步检测声音与确认后的计时状态是不同事件，声音可能早于红色暂停反馈。现有声音仍保留；不为视觉同步擅自延迟声音或新增警报音。
5. [CatUi.blocker](../../app/src/main/java/com/roy/worktoscroll/CatUi.java) 同时服务临时浮层和全屏阻止页，目前为静态到期假条图；强入场只能选择一个呈现入口，避免浮层切全屏连续盖两次章。
6. [MainActivity](../../app/src/main/java/com/roy/worktoscroll/MainActivity.java) 有真实余额驱动的首页双状态、保护状态和每日清零轻提示。后台设置“待核对”不证明发生故障，不适合红色故障演出。

## 当前设计与取代关系

- 猫总主题方案以[统一视觉语义与场景映射 v2](../../docs/design/interface-and-roles.md#visual-language)为准；本轮新增的上层[皮肤规划草案](../../docs/design/skin-system-proposal.md)负责预制成品交付、通用事件反馈、可选专属动作、插画/真人与成本；照片定制为暂缓备选。已确认交付与复用边界回写 SPEC §11.2，其余建议不升级为定论，不更改实际架构；旧离开/回归盖章分镜整体停用。
- 已同意的方向与“酷”的体验目标回写 SPEC；DESIGN 和本任务均指向同一详细章节，任务不再复制整套设计。
- 旧“大英文状态词＋中文说明”方案及先做四个节点的建议被本轮单段方案取代。已移除本任务中重复的旧详细稿，防止接续时误实施；奖励、重置、保护异常与结算的扩展继续暂缓；耗尽的强转折已按最新反馈补充设计，但尚未制作或实施。
- 用户纠正“猫总在岗”混淆主语，已纳入当前详细方案：事实状态描述用户的检测/计时，台词由猫总署名。
- 旧会话预览保留为早期探索，不代表新方案。它曾通过脚本语法及引用检查，但本地网址被浏览器工具策略拒绝，未进行浏览器视觉验证；不拿它当本轮动作样片。
- 当前代码恢复路径已由摄像头任务接续到 0.5.3；本轮核对后修正界面设计文档中旧“打开说明后不自动恢复”的过时描述，以免新动效接错事件。未修改实际恢复代码。
