# Android 多目标娱乐应用监控准备

状态：未来工作，尚未授权设计或实施。创建日期：2026-09-10。

入口：[任务索引](../README.md)。维护人：实际启动本任务的 agent；进入实施前移入 `active`，并在关键决策、验证或阻塞时维护本文件。

## 目标与范围

为 Android 版本准备“用户选择一个或多个娱乐 App 进行监控”的能力。首批候选为小红书、抖音和红果；被选中的 App 是否共用当前 Scroll Time 余额、以及余额耗尽后的具体阻止流程，须在启动本任务时结合单选/多选交互确认。

当前 Gate 1 仍只验证固定标准版小红书。本任务不因记录候选而改变当前代码、权限、数据收集、已有余额或任何已完成/未完成验收结论。

## 已确认边界

- 用户可选择一个或多个已支持的娱乐 App；首批候选是小红书、抖音、红果。
- 不承诺“任意 App 都能控制”，也不默认读取、展示或上传全部已安装 App 列表。
- 继续采用“按前台使用扣减、余额归零后显示本应用阻止页”的自律辅助边界，不声称系统级封禁、强制停止目标 App，或防止用户主动绕过。
- 每种 App、发行版本和系统版本的适配须以真实设备证据为准；不得把小红书的短测结果外推为抖音或红果已经可用。

## 启动前待确认

- [ ] 确定首版交互：单选切换、允许多选，或两者同时提供；若多选，确认同一余额在任一已选 App 前台时均扣减。
- [ ] 确定首批实际支持的安装包与版本范围，处理抖音极速版、应用分身等不同包标识的策略。
- [ ] 确定是否只显示预置且已安装的支持对象；如考虑通用应用列表，先评估最小包可见性、隐私告知和商店政策影响。
- [ ] 确定切换/改选时的规则：旧目标是否立刻停止监控，余额和历史是否共用，以及切换间隔一律不补扣。
- [ ] 确定面向用户的真实表述，避免把覆盖阻止页写成“彻底封禁”或“所有软件均可控制”。

## 实施前核查与验收

- [ ] 将当前硬编码的小红书目标抽成已支持目标配置；切换必须与账本状态原子保存，且不把未观察到的间隔计入消费。
- [ ] 对每个候选 App 分别在真实设备验证：有余额扣减、归零阻止、返回/桌面、锁屏恢复、音频、画中画、分屏/多窗口、后台冻结及服务恢复。
- [ ] 验证未安装、卸载、更新、不同渠道版本和应用分身时的清晰提示与不误拦截行为。
- [ ] 复核使用情况访问、悬浮窗、前台服务、目标 App 包可见性及国内/海外商店政策；不得为扩大适配静默增加读取完整应用列表、页面内容、浏览历史或摄像头数据的能力。
- [ ] 针对单选与多选分别覆盖账本测试、前台事件测试和真机验收；确认当前小红书耐久问题没有被多目标改动掩盖。

## 当前停点

等待当前固定小红书的后台耐久、消费耗尽与阻止体验形成足够真机证据后，再由 Roy 确认首版单选/多选交互和首批验证对象。当前未修改功能实现。
