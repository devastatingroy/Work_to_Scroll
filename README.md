# WorkToEarn 悬浮窗验证版

当前 Android 路线已由 Roy 选择为“使用情况访问 + 普通悬浮窗”，继续通过真机验证可靠性。名称仍为 **WorkToEarn 悬浮窗测试**，应用 ID `com.roy.worktoscroll.overlaytest`，版本 `0.1.1-overlay-test`，保留现有新版数据。原版应用仍独立安装，旧源码保存在标签 `checkpoint/gate1-before-overlay-20260907`；选择新版不等于完整 MVP 或公开发布验收通过。

## 当前测试顺序

1. 在原版 WorkToEarn 中停止保护，避免把原版拦截误判为新版有效；不必撤销原版授权或卸载原版。
2. 安装并打开本实验版。亲自查看“使用情况访问”和“显示在其他应用上层”的系统提示，按自己的判断授权。运行通知可单独开启，通知授权不是启动服务的必要条件。
   在 Xiaomi 设备上，第二项会说明路径并优先进入本应用设置：**权限管理 → 其他权限 → 显示悬浮窗**，避免从软件列表找应用；也保留“应用列表入口”作为备选。其他厂商继续使用标准入口，具体页面不作跨机型保证。已授权时按钮显示“悬浮窗已授权 · 查看设置”。
3. 两项必要授权完成后，在本实验版点“开启保护”，保持零余额，打开小红书。查看阻止页能否持续显示、返回测试版和桌面是否正常，以及授权提醒是否可以接受。
4. **上一步体验确认通过后**，再使用“加入 5 分钟（测试）”进行连续/分段消费、锁屏、后台持续运行、强停后重新打开等验证。按钮每次增加五分钟，清空前有确认框。
5. 结束测试时点“停止保护”，也可通过运行通知停止。需要恢复原版时停止本实验版，再在原版开启保护。

前台服务启动后显示运行通知（通知被系统禁用时展示位置由系统决定）；系统仍可能限制后台运行。此实验不承诺强停或崩溃期间继续保护，也不自动开机运行。此前开启保护且权限有效时，重新打开首页会尝试恢复；中断期间不补扣。

## 边界

- 普通悬浮窗需要敏感授权，不能保证警告更温和；目标应用可以拒绝覆盖，必须真机验证。
- 阻止方式是页面覆盖，不是系统暂停小红书；音频、分身、多窗口、画中画和防主动绕过不在本轮保证范围内。
- 本机使用事件计时；没有无障碍组件、网络、摄像头、麦克风权限。不采集屏幕正文或截图。
- [TASK.md](TASK.md) 是当前验收与恢复入口；[ARCHITECTURE.md](ARCHITECTURE.md) 记录本分支实际结构；[docs/DESIGN.md](docs/DESIGN.md) 记录实验方案边界；[docs/SPEC.md](docs/SPEC.md) 保留完整产品需求。

## 构建

JDK 17、SDK 36、Build Tools 36.1.0，配置本地 `local.properties` 后：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

安装包位于 `app/build/outputs/apk/debug/app-debug.apk`。不使用旧版安装包路径。

第一阶段接受后，可用 `.\scripts\gate1-device-check.ps1 -Serial '<设备号>' -FirstStageAccepted` 做五分钟分段检查。脚本只读实验版账本，并要求原版保护已停止；需要 `adb` 在 PATH 中。它临时修改锁屏超时并在 finally 恢复，若断线或中断须按日志中的原始值另行核对。脚本 PASS 不能替代实际阻止画面的验收。
