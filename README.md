# WorkToScroll

当前 Android 路线已由 Roy 选择为“使用情况访问 + 普通悬浮窗”，新增最小摄像头在场计时与工作奖励。名称为 **WorkToScroll**（由“WorkToEarn 悬浮窗测试”更名），应用 ID 仍为 `com.roy.worktoscroll.overlaytest`，版本 `0.2.5-protection-fix`，保留现有余额、权限和保护设置。Roy 的旧版已停用、保留数据；旧源码保存在标签 `checkpoint/gate1-before-overlay-20260907`。实现范围不等于完整 MVP 或公开发布验收通过。

## 摄像头工作奖励

工作页采用黑色背景、浅色文字和深灰按钮，减少持续亮屏的刺眼感。

1. 首页点击“开始摄像头工作”，进入工作页后点击“开始工作”。首次按自己的判断授权摄像头，再点击开始/继续。
2. 固定手机，让前置摄像头看到脸，保持工作页在前台。应用在监测期间保持亮屏，不需要修改系统自动锁屏时间。
3. 观察到一个人脸并确认约 1 秒后累计有效时间；短暂未见人脸有 3 秒容错，持续离开或检测中断暂停。多人脸、暗光、侧脸和低头可能影响检测。这只能作为基础在场线索，不能证明正在工作，也不识别身份或拿另一部手机。
4. 首次累计满 10 分钟有效时间获得 5 分钟娱乐余额，此后每累计 1 分钟获得 30 秒；会话继续，门槛与余量跨会话保留。工作页以有效时间为主，到账时轻提示，累计每十分钟展示里程碑；无声音、震动或弹窗。升级会一次性补齐旧有效时间在新旧规则下的奖励差额，单独标注并计入余额，不重置已有消费。
5. 切出、锁屏或返回首页会暂停摄像头；回来后点击“继续监测”。“结束工作并保留奖励”结束本次会话；保护独立运行，按小红书实际用量扣减。首页只突出“可用娱乐时间”，不显示待兑换余量；内部余量仍保留。务必同时查看实际保护状态。

画面仅在手机内存中处理，不保存照片/录像、不上传。请不要用摄像头是否已打开来判断计时是否有效，以页面检测状态为准。真机验证进度见 [TASK](TASK.md)，20—40 分钟耐久及完整工作奖励消费必须按实际时长验证。

## 当前测试顺序

1. 在原版 WorkToEarn 中停止保护，避免把原版拦截误判为新版有效；不必撤销原版授权或卸载原版。
2. 安装并打开本实验版。亲自查看“使用情况访问”和“显示在其他应用上层”的系统提示，按自己的判断授权。运行通知可单独开启，通知授权不是启动服务的必要条件。
   在 Xiaomi 设备上，第二项会说明路径并优先进入本应用设置：**权限管理 → 其他权限 → 显示悬浮窗**，避免从软件列表找应用，弹窗只保留“进入本应用设置”和“取消”。其他厂商继续使用标准入口，具体页面不作跨机型保证。已授权时按钮显示“悬浮窗已授权 · 查看设置”。
3. 首次进入并完成两项必要授权后，返回本实验版会默认开启保护。首页确认“保护运行中”后测试小红书；有余额时应扣减，零余额时查看阻止页及返回是否正常。不要为测试清空真实工作奖励。
4. **上一步体验确认通过后**，再使用“加入 5 分钟（测试）”进行连续/分段消费、锁屏、后台持续运行、强停后重新打开等验证。按钮每次增加五分钟，清空前有确认框。
5. 结束测试时点“停止保护”，也可通过运行通知停止。需要恢复原版时停止本实验版，再在原版开启保护。

手动停止后，关闭和重新进入都保持停止，首页持续显示“未保护”。停止满4小时后仅09:00—21:00静默提醒，两次至少间隔4小时，不响铃、不震动、不弹窗；需允许通知，系统可能延迟。再次开启保护取消提醒。升级首次采用默认开启策略，以后升级不重置用户停止选择。

前台服务启动后显示运行通知（通知被系统禁用时展示位置由系统决定）。系统中断、开机及更新后会尝试恢复，不能承诺强停、崩溃或省电限制期间仍正常保护；返回首页核查实际状态，中断期间不补扣。默认保护不会自动启动摄像头。

小米手机可从首页“检查后台运行设置”进入本应用详情，核对省电策略是否为“无限制”；系统后台配置与使用情况/悬浮窗授权分别管理。已实测存在服务仍列为运行、进程却被冻结的故障，冻结期间应用无法自行执行拦截。0.2.5补上服务启动/中断恢复时的前台状态重建、不补扣未知区间，以及中断记录；不能仅凭新版本安装成功宣称后台冻结已经解决，实际设置与持续拦截验收见 TASK.md。

复现失效时可先运行 `.\scripts\protection-health-check.ps1`，只读核对余额、监测更新时间、实际进程冻结状态、目标焦点和阻止窗口。可用 `-Samples 6 -IntervalSeconds 10` 连续采样；不会切换页面、修改余额/权限或读取页面正文。先采样再回主应用，避免前台唤醒消除故障现场。窗口被列出不代表已通过可见性与触摸验收。

## 边界

- 普通悬浮窗需要敏感授权，不能保证警告更温和；目标应用可以拒绝覆盖，必须真机验证。
- 阻止方式是页面覆盖，不是系统暂停小红书；音频、分身、多窗口、画中画和防主动绕过不在本轮保证范围内。
- 本机使用事件计时和摄像头分析；没有无障碍组件、网络、麦克风或存储权限。不采集屏幕正文或截图，离线检测模型随 APK 打包。
- [TASK.md](TASK.md) 是当前验收与恢复入口；[ARCHITECTURE.md](ARCHITECTURE.md) 记录本分支实际结构；[docs/DESIGN.md](docs/DESIGN.md) 记录实验方案边界；[docs/SPEC.md](docs/SPEC.md) 保留完整产品需求。

## 构建

JDK 17、SDK 36、Build Tools 36.1.0，配置本地 `local.properties` 后：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

安装包位于 `app/build/outputs/apk/debug/app-debug.apk`。不使用旧版安装包路径。

第一阶段接受后，可用 `.\scripts\gate1-device-check.ps1 -Serial '<设备号>' -FirstStageAccepted` 做五分钟分段检查。脚本只读实验版账本，并要求原版保护已停止；需要 `adb` 在 PATH 中。它临时修改锁屏超时并在 finally 恢复，若断线或中断须按日志中的原始值另行核对。脚本 PASS 不能替代实际阻止画面的验收。
