# WorkToScroll

WorkToScroll 帮助用户通过工作或学习攒取娱乐时间，在额度耗尽后限制娱乐使用，核心面向希望减少无意识刷小红书的城市中产阶级年轻女性。

完整产品定义与目标用户边界见 [SPEC](docs/SPEC.md)。当前先在自用 Android 手机上验证工作计时、奖励与小红书使用限制；摄像头仅提供基础在场线索，不能证明正在工作，长期可靠性仍待验证。

## 当前实现范围

当前 Android 路线已由 Roy 选择为“使用情况访问 + 普通悬浮窗”，新增最小摄像头在场计时与工作奖励。**WorkToScroll** 构建仍使用应用 ID `com.roy.worktoscroll.overlaytest`，当前代码基线为 v53 `0.5.31-night-relax-preview`（实际安装与验收见[任务索引](tasks/README.md)），保留猫总界面、现有余额、权限和保护设置。Roy 的旧版已停用、保留数据；旧源码保存在标签 `checkpoint/gate1-before-overlay-20260907`。实现范围不等于完整 MVP 或公开发布验收通过。

当前源码沿用 v46 的 320×240、统一 0.50 可靠门槛和低负载回退边界，并在其上加入夜间放松额度与自动临时预览，形成 v53；当前源码不含 v49–v52 的分辨率对照实验采样。实验记录和图片保留在[结项任务](tasks/completed/side-rear-presence-exploration.md)。源码、构建、安装与真机体验仍分别记录，不能相互替代。

## 猫总首页

桌面图标采用紫底、暖白票券与标准沙漏；其他候选保留在[图标备选归档](docs/design/app-icon-exploration.html)。首页猫总角色继续保留。

首页显示猫总、真实可用娱乐时间与累计已工作时间。“开始工作/继续工作”进入黑色工作页；有余额时可点“去小红书”，零余额时先工作攒时间。奖励自动到账，无需领取。

首次进入当前规则版本展示规则引导。右上角“设置”把保护控制、授权摘要、娱乐规则及帮助分开；“权限与后台保障”详情按必需授权、重要后台保障、可选通知排列。停止保护前确认后果，异常直接显示处理入口。首页保护状态可点击进入设置，异常不会因界面简化而隐藏。猫总只回应已有状态：持续离开举牌、奖励到账盖章；新消费耗尽时，阻止页播放一次猫总“时间到了！”；原本零余额、每日清零或来源不明时静态说明，不重复表演。多角色选择尚未实现。

## 娱乐规则

每日清零默认开启：每天本地时间 06:00 清空剩余娱乐，设置可关闭。新安装或首次升级从下一个 06:00 生效，不立即清空；以后升级保留用户选择。关闭不恢复已到期余额，再开启从下一次 06:00 开始。首页显示下一清零时间，清零后提示一次。

清零只影响可用余额，不删除工作历史、不计入实际消费，也不打断跨 06:00 的本轮工作；新到账奖励保留到下一截止点。关机、系统冻结或强停期间不保证当场执行，恢复时先处理到期余额。自然跨夜及后台可靠性仍需真机验收，见[娱乐规则任务](tasks/active/entertainment-rules.md)。

夜间放松默认开启：每晚 22:00–08:30 送一份固定放松额度（默认 45 分钟），让夜里没那么紧。窗口内先花这份免费额度，用完后按你攒的余额照常保护、余额也空了才拦；08:30 额度作废、自动恢复白天的正常保护。放松额度不倒扣赚来的余额、也不计入娱乐消费；每晚刷新一次，用不完不累计，半夜重启保留当晚剩余。设置可关闭并显示今晚剩余额度。窗口边界不依赖精确闹钟，只“少拦”不引入新的必须可靠触发；真机跨夜行为仍需验收，见[夜间放松额度任务](tasks/active/night-relax-quota.md)。

## 摄像头工作奖励

工作页采用黑色背景、浅色文字和深灰按钮，减少持续亮屏的刺眼感。

1. 首页点击“开始工作”，进入工作页后点击“开始监测”。首次按自己的判断授权摄像头，再点击开始/继续。
2. 固定手机，让前置摄像头朝向肩部和躯干，手机可放在侧后方，无需露出人脸。背影与椅背遮挡效果仍在试用验证，保持工作页在前台。应用在监测期间保持亮屏，不需要修改系统自动锁屏时间。
   当前试验版每次主动开始后先持续展示自拍预览 10 秒，随后自动收起；收起后可点击“预览已收起，监测继续 · 查看机位”，随时重新打开一次新的 10 秒预览。程序收起时只解绑自拍 Preview，并把工作页窗口亮度覆盖值设为 0.05（不是把面板实际亮度固定为 5%），但继续本机人体分析、计时、声音和奖励；重新打开时撤销该亮度覆盖。自动恢复仍保持预览收起；主动暂停后重新开始会恢复预览，便于重新校准机位。
3. 至少可靠观察到一个人体并确认约 1 秒后累计有效时间；额外候选或多个可靠人体不会单独造成暂停。已经可靠确认在场后，较弱人体结果连续不足约 3 秒仍继续记录，持续满约 3 秒才暂停；较弱结果不能从零开始建立在场，暂停后仍需约 1 秒可靠结果才能恢复。完全未见人体时立即播放“滴～暂时离开”，计时仍有 3 秒短暂容错；弱结果与零候选之间切换不会叠加两套宽限。异常停计时立即显示红色“已暂停计时”并全屏琥珀色慢闪三次（每次约1秒），识别不可靠播“未能确认有人，计时暂停，请让身体多露出一些”，相机/处理异常播“监控中断，已暂停计时”。首次异常暂停立即语音加三次慢闪；以首次提醒触发为t，持续未恢复时在t+30秒、1分钟、2分钟、4分钟、8分钟等倍增时点同时播语音并全屏慢闪三次。只要真正恢复有效计时，就清除本次提醒序列；再次异常暂停立即重新声光提醒，不设跨暂停60秒限频。确认态、原因变化和三分钟本轮清零不重启序列。静音不取消首次及后续视觉提示，但跳过该时点语音；通话/其他媒体抑制的语音也不补播，只等待后续提醒时点。不显示原因说明，详细原因写日志。恢复计时立即取消闪动和未结束的暂停语音，并在已提交可计时状态后播报一次“恢复计时”，不闪屏；暂停后的确认阶段主状态仍保持“已暂停计时”，不提前播“欢迎归来”。首次正常开始和计时未停的短暂缓冲恢复不播“恢复计时”；异常、明确离开、手动继续或正常切换后真正恢复均适用。声音关闭或音频环境不允许时不强播、不补播；再次暂停、切出或结束取消未完成的恢复语音。零候选保留即时“暂时离开”，不闪屏也不重复暂停警告。正常切出、来电、锁屏、失焦和主动暂停不报警、不积压补播；返回后重新获得画面仍识别失败或相机恢复失败才提示，正常返回不播“欢迎归来”。声音遵循原开关与媒体音量，通话/其他媒体/静音时不强播。人体检测仅提供基础在场线索，不识别身份或证明正在工作。
4. 默认每轮先满 10 分钟得 5 分钟，此后每分钟再得 30 秒；设置可选 15 换 5（之后每分钟 20 秒）、20 换 5（之后每分钟 15 秒）。修改从下一轮生效，不重算本轮。现有 3 秒识别容错后，连续离开/暂停不足 3 分钟可续接，达到 3 分钟则本轮进度与奖励资格归零，重新过所选档位门槛。工作页显示暂停倒计时与重置说明，已到账奖励和历史工作保留；到账轻提示，不响铃、震动或弹窗。升级不追扣已获得余额，也不根据历史总量追加奖励。
5. 切出、锁屏、打开说明会暂停摄像头；短暂切去其他应用后，从最近任务或桌面图标在 90 秒内返回会自动回到工作页并重新确认在场。点击暂停、工作页返回、结束工作、强停、划掉最近任务或重新开机后仍需手动继续。“结束工作”结束本次会话并保留已到账奖励，下次重新累计所选档位的首次门槛；保护独立运行，按小红书实际用量扣减。首页只突出“可用娱乐时间”，不显示待兑换余量；余量仅在同一轮短暂停中保留。务必同时查看实际保护状态。

检测首次明确及有人/未见人切换时分别播“欢迎归来”和“滴～暂时离开”，同状态不复读，声音不等待计时确认或离开宽限。工作页可关声音，媒体音量不被应用自动调高；声音表示检测变化，不代表计时立即开始或暂停。画面仅在手机内存中处理，不保存照片/录像、不上传；最新数值诊断保存在本机，便于 Agent 读取，不能以旧读数判断当前在场。真机验证进度见 [任务索引](tasks/README.md)，20—40 分钟耐久及完整工作奖励消费必须按实际时长验证。

当前使用 MediaPipe Object Detector + 随包 EfficientDet-Lite0 人体模型，在手机本地运行。0.5.9 发热工程试验版把前置预览和分析目标降至 320×240、请求固定 10fps，并把人体推理上限降至每秒一次；本机已核对实际320×240与[10,10]请求，约33分钟温升体验基本通过，长期识别体验仍待日常观察。关闭屏幕预览不等于关闭相机或人体分析。画面处理后释放，暂停或离开工作页时关闭摄像头。本机保留工作/奖励账本与检测数值状态，不积累录像；调试构建另保留有大小上限的本次工作事件日志，用于跨轮次重置核对有效时间和中断，0.5.18 起还会在本轮首次开始及点击结束时各读取一次系统电池状态并汇总温差，不做连续温度采样。遇到检测异常可用[摄像头状态读取脚本](scripts/camera-health-check.ps1)检查；核对本次有效时间与温度端点可用[工作会话调试脚本](scripts/work-session-debug.ps1)，读数解释见[调试经验](notes.md#摄像头检测状态读取)。

## 当前测试顺序

1. 在原版 WorkToEarn 中停止保护，避免把原版拦截误判为新版有效；不必撤销原版授权或卸载原版。
2. 安装并打开本实验版，从“设置 → 权限与后台保障”进入授权。亲自查看“使用情况访问”和“显示在其他应用上层”的系统提示，按自己的判断授权。运行通知可单独开启，通知授权不是启动服务的必要条件。
   在 Xiaomi 设备上，第二项会说明路径并优先进入本应用设置：**权限管理 → 其他权限 → 显示悬浮窗**，避免从软件列表找应用，弹窗只保留“进入本应用设置”和“取消”。其他厂商继续使用标准入口，具体页面不作跨机型保证。已授权时独立显示“已授权”和“查看系统设置”入口。
3. 首次进入并完成两项必要授权后，返回本实验版会默认开启保护。首页确认“保护运行中”后测试小红书；有余额时应扣减，零余额时查看阻止页及返回是否正常。不要为测试清空真实工作奖励。
4. **上一步体验确认通过后**，再到“设置 → 开发工具”使用“加入 5 分钟（测试）”进行连续/分段消费、锁屏、后台持续运行、强停后重新打开等验证。按钮每次增加五分钟，清空前有确认框。
5. 结束测试时到“设置”点“停止保护”，也可通过运行通知停止。需要恢复原版时停止本实验版，再在原版开启保护。

手动停止后，关闭和重新进入都保持停止，首页持续显示“未保护”。停止满4小时后仅09:00—21:00静默提醒，两次至少间隔4小时，不响铃、不震动、不弹窗；需允许通知，系统可能延迟。再次开启保护取消提醒。升级首次采用默认开启策略，以后升级不重置用户停止选择。

前台服务启动后显示运行通知（通知被系统禁用时展示位置由系统决定）。系统中断、开机及更新后会尝试恢复，不能承诺强停、崩溃或省电限制期间仍正常保护；开机恢复会记录“收到广播、请求服务、服务启动、缺授权或系统拒绝”等最小结果，返回后可核查实际状态，中断期间不补扣。默认保护不会自动启动摄像头。

小米手机还需在“设置 → 权限与后台保障”分别核对三项：省电策略为“无限制”、允许 WorkToScroll 自启动、锁定最近任务；系统后台配置与使用情况/悬浮窗授权分别管理。自启动入口随 HyperOS 版本变化，应用会说明可搜索“自启动”，但不能代开或可靠读取该厂商设置。已实测存在服务仍列为运行、进程却被冻结的故障，冻结期间应用无法自行执行拦截。0.2.5补上服务启动/中断恢复时的前台状态重建、不补扣未知区间，以及中断记录；不能仅凭新版本安装成功宣称后台冻结已经解决，实际设置与持续拦截验收见[后台保护任务](tasks/active/background-protection.md)。

复现失效时可先运行 `.\scripts\protection-health-check.ps1`，只读核对余额、监测更新时间、实际进程冻结状态、目标焦点、阻止窗口，以及 0.5.10 起的开机恢复结果和启动编号。可用 `-Samples 6 -IntervalSeconds 10` 连续采样；不会切换页面、修改余额/权限或读取页面正文。开机验收须在解锁后、首次打开 WorkToScroll 前采样，避免前台唤醒消除故障现场。窗口被列出或服务请求已发出不代表已通过可见性、触摸或恢复验收。

监测中遇来电、电量弹窗、通知栏、切出或锁屏会暂停；回到可交互的工作页后自动尝试恢复，重新确认在场后才计时。短暂切去其他应用后若桌面图标把用户带到首页，只有同一进程内 90 秒的一次性返回凭证才会自动回到工作页；它不会在后台、锁屏、首页、冷启动或显式暂停后打开相机。正常切换不声光报警、不补播；返回仍无法恢复时即时声光提醒，页面只显示暂停状态与继续入口。中断不补计，三分钟重置规则不变。真实来电和系统弹窗验收见[摄像头任务](tasks/active/camera-rewards.md)。

## 边界

- 普通悬浮窗需要敏感授权，不能保证警告更温和；目标应用可以拒绝覆盖，必须真机验证。
- 0.3.4先用浮层遮挡，再打开工具自己的全屏阻止页，让小红书退到后台；保留返回工具/桌面按钮，系统返回也回桌面。后台启动被系统拒绝时保留浮层，不能据此保证停声。音频焦点仅辅助，不改手机音量或自动恢复播放；同时播放的后台音乐可能暂停（Roy已接受）。0.3.2单靠焦点的方案已被持续出声反馈否定，Roy已确认全屏页切换后停止出声，最终版本的重复进入与返回验收见音频任务；分身、多窗口、画中画和防主动绕过不在保证范围内。
- 本机使用事件计时和摄像头分析；没有无障碍组件、网络、麦克风或存储权限。不采集屏幕正文或截图，离线检测模型随 APK 打包。
- [任务索引](tasks/README.md) 是当前验收与恢复入口；[ARCHITECTURE.md](ARCHITECTURE.md) 记录本分支实际结构；[docs/DESIGN.md](docs/DESIGN.md) 记录实验方案边界；[docs/SPEC.md](docs/SPEC.md) 保留完整产品需求。

## 构建

JDK 17、SDK 36、Build Tools 36.1.0，配置本地 `local.properties` 后：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

该命令会同时构建并测试两个产品变体。安装包分别位于：

- WorkToScroll：`app/build/outputs/apk/workToScroll/debug/app-workToScroll-debug.apk`
